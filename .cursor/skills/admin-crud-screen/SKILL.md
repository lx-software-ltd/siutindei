# Admin CRUD screen

Build list screens from `apps/admin_web/src/components/ui/`.

- Page-level table cards are an untitled white `Card` (`AdminRecordTable`) with four slots: optional filters left, optional actions left on a **new** row, the table, optional Load more. Nothing else inside the card. Workspace pages show the open organization's name and status badges above that table card, and an sr-only heading with the page name. The Organization input card puts the name and badges in the card title. A new organization uses the card title "New organization" with no badges. An existing organization with no name uses "Organization".
- Filters (`AdminFilterBar` + `AdminFilterField`) are left-aligned fields only. `AdminCreateButton` spells out its label at every breakpoint, matches `Button` `md` (`h-10` below `sm`, `h-9` from `sm`, `w-auto`), and sits on the `actions` row. Filters apply on change. Text filters are debounced. Placeholders name what the field matches (`Name or address`), not “Search …”. The accessible name stays the record noun (`Activity`) so it does not collide with a field label. Do not render Apply or Clear. Omit empty filter bars, including a bar whose children are all `false`. Catalog filters sit inside the table card. On Map, that same bar sits above the map card and is not repeated inside it. Import and organization scope notes sit above the card, after the sr-only page heading, with **Show all**.
- Rows expand in place (`AdminExpandableRow` + `useExpandedRecord`). One row is open. Do not put `border-x-*` on expandable rows. Create inserts a draft row (`DRAFT_RECORD_ID`, URL value `new`).
- Editors (`AdminEditorPanel` + `AdminEditorActions`) have no title and no Cancel button. Fields use `AdminField` inside `AdminFieldGrid`. Field titles are `font-semibold` (same weight as Import / History / File warnings). Field errors are the `error` prop (`AdminInlineError`). Do not hand-write `text-xs` or `text-sm` with `text-red-600`. Read-only details use `AdminReadOnlyValue` (`dl` / `dt` / `dd`). Unsaved edits use `AdminDiscardChangesDialog`. The action bar renders only when it has actions.
- Input cards are `AdminInputCard`: required title (`text-base font-semibold sm:text-lg`), variable content, and a bar when there are actions (`border-t border-slate-200 pt-4`). Omit the bar when there are no actions. A card under the page heading uses `titleLevel="h3"`. Card chrome is `Card`. Do not invent a dummy button when there is no action. Login and dialog overlays stay on `Card`. Expanded row editors stay on `AdminEditorPanel` inside the table card. Results that follow a submit, such as an import summary, use the `footer` slot so they sit below the bar.
- Banners use `StatusBanner` `kind`: `error`, `saved`, `pending-review`, `info`. Pass `title` only to override the heading. Do not also pass `variant`.
- Chips use `AdminToggleChip`. Create, sweep, and bulk decide go in the table `actions` row (`justify-start`). Apply and Dismiss are `secondary`. The Catalog release toggle is a `Button` (`aria-pressed`) on that row, not a checkbox, and it clears after a successful bulk action. Omit the row when there is no button. Banners, count lines, scope notes, and Refreshing sit above the card. A failed list hides the empty-table sentence. Count lines say Loading… until the summary arrives. Submit buttons on narrow screens use `w-full sm:w-auto`.
- Dialogs use `AdminDialog`. `ConfirmDialog` is the confirm/cancel footer. `footer={null}` omits the footer.
- Operations use `AdminRowActions`. More than two actions: the first stays inline and the rest go in the menu. Tables with no row actions omit the Operations column.
- Mobile: no `min-w-*` on record tables. Non-essential columns use `priority='secondary'` or `priority='tertiary'`. A tertiary column does not sit before a later secondary column. Each hidden column is repeated under the name with `AdminDataTableCellMeta` in column order.
- Table cells use one role: `AdminTableName`, plain text, `AdminTableTime`, `StatusBadge`, `AdminTableId`, `AdminTableNumber`, or an em dash (`—`). One fact per cell. A list of the same role is allowed. Confidence and other 0–1 fractions use `formatAdminTablePercent`. `AdminDataTableCell` `className` is layout only (`w-*`, `pr-0`, `whitespace-nowrap`, `text-right`, `text-center`, `py-8`); a bad class warns in development. Hidden columns repeat under the name with `AdminDataTableCellMeta`; an empty caption includes the column name (`Expires —`). Draft cells inherit each header’s `priority`. The Users provider icon is the one icon-valued status (`role="img"`). It sits after the email in the Email column. A missing API key expiry is an em dash. A key with no organization is the text `Full access`.
- In-flight buttons use `Button` `loading`. Loading tables use `AdminSkeletonRows`.
- Server state is TanStack Query via `getAdminQueryClient()`, `adminQueryKeys`, and `usePaginatedList`. `useResourceEditor` is the list and editor hook for resource-api screens.
- Read-only records still expand in place. Do not add a detail dialog for them.
- In-area switchers use `AdminTabStrip`. Tab labels are sentence case.
- Page name is the nav label when there is no tab, or the tab is the default and repeats the nav (`Imports`, `Categories`, `Feedback`, including an `-ies` plural such as Activities / Activity). Otherwise the page name is `Nav · Tab` (`Imports · History`, `Categories · Suggestions`, `Data quality · Names`). Use `formatAdminPageName(nav, tab)` from `apps/admin_web/src/lib/admin-page-name.ts`, and take tab text from `adminTabLabel`. Do not invent fused phrases (`Import history`, `Your activities`). Sub-tabs (Catalog Table / Map) are not part of the page name. Sidebar shows nav; the strip shows the tab. The table `aria-label` and the page's sr-only heading use the page name.
- Deep links use `?<entity>=<id>`. `org` is the workspace organization and stays across workspace sections. Legacy `?organization=` and `?edit=` still open that organization.
- Organization media stays a drag-reorder grid. There is no Cancel control. Leaving the section deletes uploads that were not saved.

## Done

`npm run lint` and `npm run typecheck` pass in `apps/admin_web`, and the Playwright spec for the screen matches the labels.
